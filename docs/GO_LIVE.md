# Go-live runbook (real data)

The production pipeline only counts as live after a **real** review has gone from the Content
API to a published page with a verified Sovrn offer. Follow these steps in order. Nothing here
wipes or replaces production data.

## 1. Credentials (Vercel → Settings → Environment Variables, Production, "Sensitive")

| Variable | Notes |
|---|---|
| `CONTENT_API_URL`, `CONTENT_API_KEY` | Plus `CONTENT_API_AUTH_HEADER` / `CONTENT_API_AUTH_SCHEME` if the API doesn't use `Authorization: Bearer`. |
| `SOVRN_API_URL`, `SOVRN_API_KEY` | `SOVRN_API_KEY` is the **secret** API key. The public site key (`SOVRN_SITE_KEY`, already set) is a different credential; the preflight fails if they are equal. |
| `GSC_SITE_URL`, `GSC_SERVICE_ACCOUNT_JSON` | Add the service account's `client_email` as a user on the Search Console property first. |
| `PEXELS_API_KEY`, `CRON_SECRET`, `DATABASE_URL`, `DIRECT_URL` | Already set. |

None of these may use a `NEXT_PUBLIC_` prefix. Redeploy after changing them.

## 2. Preflight (read-only)

**Admin → Go-live checks → Run checks.** It runs in the deployment, with its own secrets, and
makes one request per provider. It writes nothing except an audit-log entry with the statuses.

| Result | Meaning |
|---|---|
| `OK` | Authenticated, response parsed. Details show field coverage, dates, pagination, offer counts. |
| `EMPTY` | Provider answered with no items/offers for that request (not an error). |
| `AUTH_FAILED` | Credential rejected (401/403). For Sovrn this usually means the site key was used as the secret. |
| `INVALID_RESPONSE` | Response shape doesn't match what the adapter parses. **Do not ingest**: send the details to engineering so the adapter is fixed against the real contract. |
| `BLOCKED_BY_ENVIRONMENT` | Not configured. |

`npm run live:check` runs the same checks from a machine that has the variables.

## 3. Limited real run

1. Keep `AUTO_PUBLISH_ENABLED=false`. Set `INGEST_MAX_ITEMS_PER_RUN=10`.
2. Admin → Overview → **Run ingestion now**. Check Ingestion (invalid items and reasons),
   Entities and Categorization (low-confidence items), Deals (`MATCHED` / `NO_MATCH` /
   `FAILED`), Link health (`VERIFIED_OK` share) and Failures.
3. Publish two or three reviews from the QA queue by hand. Open each public page: source
   attribution, dates, image credit, "Verified offer" only where the link is `VERIFIED_OK`.
4. Click one "View deal" link and confirm it lands on the merchant.
5. Confirm the pages appear in `/sitemap.xml`. Jobs → run `inspect-index` for GSC status.

## 4. Continuous operation

Set `AUTO_PUBLISH_ENABLED=true` and raise `INGEST_MAX_ITEMS_PER_RUN` (default 50). Vercel
Hobby runs each cron once a day; for the intended cadence set the GitHub secrets `SITE_URL` and
`CRON_SECRET` (activates `.github/workflows/scheduled-jobs.yml`) or move to Vercel Pro.

## 5. Evidence

`npm run mvp:verify` (with `DATABASE_URL`) and Admin → Day-30 report. The report is labelled
`PRODUCTION` only when generated by the production deployment and every content source in the
window is a real feed; otherwise `SAMPLE_OR_TEST`, with the reasons.
